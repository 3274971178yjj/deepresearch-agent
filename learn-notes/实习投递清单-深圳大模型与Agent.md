## 一、先讲清楚：深圳的岗位供给和北京不一样

这是投递前必须知道的结构性事实，否则你会把力气用错地方。

你手上两个项目的能力标签是：

| 项目 | 你实际证明的能力 | 对口岗位名 |
|---|---|---|
| **Shopping-GRPO** | 强化学习后训练、奖励设计、轨迹数据集、veRL | 大模型后训练 / RLHF / 算法工程师（训练侧） |
| **DeepResearch Agent** | 多智能体编排、异步系统设计、评测体系、RAG/记忆 | Agent 应用 / 大模型应用算法 / 后端（AI 平台） |

**问题在于：**

1. **"大模型后训练 / RL" 岗位在深圳非常少。** 深圳不是大模型训练的主战场（北京、杭州、上海才是）。深圳真正有自研预训练/后训练团队的不超过一手之数：**腾讯混元、华为盘古、元象 XVERSE、微众 AI Lab**。其余的"大模型岗"绝大多数是**应用层**（RAG、Agent、微调、评测）。
2. **"多智能体编排"几乎没有专门招的岗位名。** 你的 DeepResearch 项目**不会**让你命中某个叫"多智能体工程师"的 JD。它的真实作用是**证明你能徒手搭系统**——这在面试里比岗位名对口更值钱，但需要你在打招呼话术里主动点出来（见第五节）。
3. **深圳真正大量招算法实习的地方是**：金融科技（平安系、微众、招行、招联）、制造业 AI（比亚迪、富士康、思谋、汇川）、机器人/具身智能（大疆、优必选、逐际动力、越疆）、推荐/广告算法、以及腾讯系的一堆应用团队。

**结论：不要只搜"大模型训练实习"。** 你的搜索词应该更宽：`Agent 实习`、`大模型应用 实习`、`NLP 算法实习`、`算法实习生`、`LLM 实习`、`RAG 实习`。

**你的打法**：

> 用 **DeepResearch** 作为"工程能力 + 系统设计"的主证据去敲所有偏应用的岗位；
> 用 **GRPO** 作为"我懂训练、不是只会调 API"的差异化标签，去敲那少数几个训练岗。

## 二、日常实习简历：你现在缺一块东西

**这一节比公司清单更重要，先看。**

日常实习的 HR / 技术面试官筛选简历时，**第一眼看的是"这周能不能来、能待多久"**，不是项目。因为日常实习的 HC 是跟着项目工期走的，来晚了两周就没位置。

你的简历现在**只有项目经历**，缺了日常实习最关键的四个字段：

```
【必须加】
· 可到岗时间：2026年10月（随时）
· 可实习时长：6 个月（2026.10 – 2027.03）
· 每周到岗：5 天（on-site）
· 期望城市：深圳

【建议加】
· 学历背景：西北工业大学 · XX专业 · 硕士/本科 · 毕业时间 2027.06
· 联系方式：手机 / 邮箱
· 技术栈一行：Python / asyncio / PyTorch / veRL / GRPO / LLM Agent / RAG / SQLite
```

**⚠️ 一个你必须先想清楚的问题：你在西安念书，深圳的日常实习要 on-site。**

深圳的日常实习**默认要求** onsite、每周 4–5 天、连续 3–6 个月。这跟在校上课是冲突的。所以你只有三条路：

| 情况 | 可行做法 |
|---|---|
| 大四/研三，课基本修完 | ✅ 直接投 onsite，最理想 |
| 还有课，但能申请到校外实习 | ✅ 投，但要在话术里说明"导师已同意" |
| 课不能停 | ⚠️ 只能投**支持远程**的（实验室、部分小厂容易谈）；大厂日常实习基本不允许全远程 |

**这个问题没想清楚就海投，会在第一轮沟通就浪费掉大量时间。** 建议先在话术里准备好这个问题的答案。

## 五、打招呼话术（每一天都要用，值得花 30 分钟打磨）

BOSS直聘 上技术负责人 / HR 每天收到几十条"你好，我想应聘实习生"。**你的话术必须在 3 秒内让他知道"你跟别人不一样"。**

### ❌ 反面模板（90% 的人都这么发）

> 您好，我是西北工业大学的学生，想应聘贵司算法实习生岗位，我的简历已发送，期待您的回复。

**问题**：没有任何信息让 HR 判断你值不值得点开简历。

### ✅ 正面模板（直接复制改）

```
您好，我投的是【算法实习生】岗位。

我匹配这个岗位的两点：
① 我做过一个多智能体编排系统（DeepResearch Agent），
   手写 asyncio + DAG 分层调度，9 状态状态机，三级降级策略，
   约 1.4 万行，配了完整评测体系（Bootstrap 置信区间 + 效应量）。
② 我做过大模型强化学习后训练（Shopping-GRPO），
   基于 veRL 做在线 GRPO，2B 模型严格成功率 0% → 62%，
   单卡 96GB 显存内完成训练。

可实习时长 6 个月，每周 5 天到岗，随时可入职。
简历在附件，期待沟通。

【你的名字】
```

### 拆解：为什么这个模板有效

| 元素 | 作用 |
|---|---|
| 第一句就点名岗位 | 显示你不是群发的 |
| **数字**（1.4万行 / 0%→62% / 96GB） | 唯一能让人记住的东西。HR 每天看几十份"熟悉 Python、了解大模型" |
| **具体技术词**（asyncio、DAG、veRL、GRPO、Bootstrap） | 让技术负责人立刻知道"这是同行" |
| 可实习时长 / 天数 / 到岗时间 | 日常实习 HR 最关心的三个字段，**放在话术里而不是只放简历里** |
| 句式短、不堆形容词 | 没有"精通""热爱""有强烈的学习能力"这类废话 |

### 按岗位类型微调

| 岗位 JD 关键词 | 你把哪个项目提前 | 强调的词 |
|---|---|---|
| Agent / 多智能体 / 工作流 | **DeepResearch 放第一** | 状态机、DAG 调度、降级、上下文压缩、共享记忆 |
| 大模型应用 / RAG / 检索 | **DeepResearch 放第一** | 向量检索、语义去重、矛盾检测、三级压缩 |
| 大模型训练 / RLHF / 后训练 | **GRPO 放第一** | veRL、GRPO、奖励设计、轨迹采集、动态采样 |
| 算法评测 / 数据 | **两个都提，强调评测** | ResearchBench、Bootstrap CI、Cohen's d、区分度校验 |
| 金融风控算法 | **GRPO 放第一**（奖励设计≈风控策略） | 奖励函数设计、硬门控、分级加权、规则引擎 |
| 具身智能 / 机器人 | **DeepResearch 放第一** | 多智能体协作、规划-执行-验证闭环 |

### ⚠️ 一句话的风险提示

你的 **`0% → 62%`** 这个数字很抓眼，但它来自 Shopping-GRPO（另一个项目、另一个仓库）。
**面试官一定会追问细节**："advantage 为零你是怎么发现的？""有界动态采样具体怎么实现的？"

**如果这个项目不是你亲自做的每一个细节，就不要在话术里把它放第一。** 数字越漂亮，被追问得越深。
DeepResearch 你手上有全部代码（我们能一起查每行），**这是你最安全的武器**；GRPO 要看你对它的掌握程度。

### 6.1 结论先行

**全自动投递脚本：对你不做。** 下面是理由，不是道德说教。

### 6.2 各平台"官方有没有批量投递"（**这决定你要不要脚本**）

| **实习僧** | ✅ **有**（详情页一键 + 列表多选批量） | 需要先设默认简历；部分职位要填求职信/筛选题，**这类不能批量**。**日常实习的主力渠道，这条对你最有用** | B− |

| **拉勾** | ✅ 有（主打"一键投递"） | | B/C |

| **领英中国** | ⛔ **平台已停服** | 领英职场（InCareer）**2023-08-09 已正式停止服务**，中国区转 B2B。别再考虑 | B |

**这张表最重要的一行是第二行**：日常实习的主力渠道 **实习僧，官方就支持批量投递**，合规、够用、不用脚本。

而要说明的是 —— **"官方没有批量"的最大池子恰好是 BOSS直聘**，所以第三方脚本几乎全在做 BOSS。这就是矛盾点所在。

### 6.4 风险（事实与推断严格分开）

**A 级事实（来自一手原文）：**

1. **geekgeekrun 作者自己的免责声明**：建议用户"**注册一个本程序专用的新的 BOSS直聘账号**进行求职"、"注意节制，当天开聊次数用尽后隔几天再使用"。**作者建议用小号，本身就说明开发者承认主号有风险。**
2. **boss-helper README 原文**："使用该脚本有一定风险(如黑号,封号,权重降低等)，本项目不承担任何责任"。
3. **第一手封号证词**：V2EX 帖 [t/948043](https://www.v2ex.com/t/948043) 中，一位自称字节招聘相关岗位的用户写道："**因为用这种脚本，我被 Boss 封过号**"。
4. **HR 侧反感是真实的**：V2EX 帖 [t/1119512](https://www.v2ex.com/t/1119512) 热门回复 —— "疯狂海投？然后招聘方的邮箱里人均几万个简历，大家都别想好好找工作"、"最后成了招聘界的 **ddos 攻击**"。

**C 级推断（高置信但没拿到可点开原文）：**

- BOSS《用户服务协议》明确禁止自动化程序/脚本/插件及批量操作，违规可封号。**（与上面两个作者自认操作违规相互印证，可信度高）**
- 2023 年杭州互联网法院受理过"全国首例简历代投不正当竞争案"（被告做代投服务、绕平台验证码与 IP 限制）。**方向可信，但具体案号/赔偿金额我拿不到可靠来源，请勿引用数字。**

**后果链条：** 封号/永久封禁（有第一手证词）→ 验证码频发、限流 → 被 HR 标记"海投"拉黑 → 申诉成功率低。

### 6.5 对你的 ROI 判断：负的

**这是本节的结论，五条理由：**

1. **瓶颈不在投递速度，在匹配质量。** 你投的是算法/大模型岗，这类简历要对着 JD 改项目表述。脚本只能把**同一份简历**撒 150 次 —— 而 LLM 批量生成的招呼语现在已经千篇一律，HR 一眼能看出来量产的。
2. **日常实习有一个脚本覆盖不到的主渠道：直接找技术负责人。** 邮箱 / GitHub issue / 知乎 / 即刻 私信 —— 这恰恰是你这种"有 1.4 万行自研系统"的人最容易出效果的路子，而脚本完全做不到。
3. **维护成本 > 收益。** 平台改版即失效（开发者自己承认）。你该复习八股、准备面试的时间，不该用来修 Selenium 脚本。
4. **下行风险不对称。** 收益上限 = 每天省 30–60 分钟；下限 = 你日常实习的**主战场 BOSS 账号**被封。日常实习没有"错过窗口"的问题，但**账号被封等于渠道直接没了**。
5. **⚠️ 对你个人还有一个特殊减分项**：你的简历卖点是"自研多智能体系统"。如果面试官问"你用过 Agent 做什么"，而你答"写脚本绕平台风控投简历" —— **这一句能把你整个 Agent 项目的可信度拉低**。同样的能力，用在简历定制、面经复盘、投递追踪自动化上，是合规的正面故事。

### 6.6 推荐组合（按优先级，全部合规）

```
① 实习僧官方批量投递          ← 日常实习主力，官方功能，直接用
② BOSS直聘：手动 + 快捷语 + 筛选器 + 用满 150 次/日额度
   （搜索筛选器是官方给的，不是脚本；这是官方允许的上限）
③ 网申表单自动填表插件，人工确认后提交
④ 直接找团队技术负责人（邮箱/私信）← 转化率最高，脚本替代不了
⑤ 投递追踪表沉淀复盘
```

**两个值得单独说的合规工具：**

- **[magicapple123/ResumeForge](https://github.com/magicapple123/ResumeForge)（简历通，211★，本地优先）**
  功能里有一条对你**特别对症**：**"事实台账防虚构"** —— 维护一份事实来源，简历只能引用台账里的事实。
  你这几轮一直在处理的正是"哪些数字能写、哪些不能编"（`85%→95%`、`992→800`、架构盲区）。
  **它把你的手工流程工具化了**，值得看一眼。
  商用替代：超级简历 WonderCV、或你自己现有的"简历句 ↔ 代码行号"索引体系（那套已经在干这件事了）。

- **[TshyGO/resume-form-assistant-plugin](https://github.com/TshyGO/resume-form-assistant-plugin)（146★，2026-10 仍在更新）**
  AI 解析简历 + **网申表单自动填写**，人工确认后提交。
  **注意它只填表、不提交** —— 这是关键区别，它不碰平台风控。
  通用替代（更稳）：Chrome/Edge 自带的地址与自定义字段自动填充，或 Bitwarden（免费开源）存一份"网申标准答案库"（可实习时长、项目一句话、期望城市…）。

### 6.7 一句话

> **别写脚本。** 把力气花在三件事上：简历头补上"可实习时长"、话术里放具体数字、以及**直接找团队技术负责人**。
> 前两件是准备工作，第三件的转化率是任何脚本都到不了的。
