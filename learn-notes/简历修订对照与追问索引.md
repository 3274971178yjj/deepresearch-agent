### 第 ② 句 · 编排引擎（**主战场，未改动**）

**原文（未改动）**：基于 asyncio+Semaphore 自研多智能体编排引擎，实现 DAG 拓扑并发执行与 9 状态状态机任务生命周期管理，支持动态 replan 与三级降级策略（单任务超时→批量失败重规划→全局超时强制合成）。

**为什么不动**：**逐字对得上**。这是你全篇最经得起拷打的一句，面试时应该主动把话题往这里引。

**要背准的五个数**（👉 [default.yaml:109-120](../configs/default.yaml#L109-L120)）：

| 参数 | 值 |
|---|---|
| 最大并发 | **5** |
| 全局超时 | **600 秒** |
| 最大重规划轮数 | **3** |
| 单次规划最大子问题数 | **10** |
| 子 Agent 最大重试 | **2** |

**三级降级的精确阈值**（👉 [orchestrator.py:519-537 `_should_replan()`](../src/orchestrator/orchestrator.py#L519-L537)）：

```
第 1 级：单个子任务超时 → 标记后继续，不阻塞整层
第 2 级：失败率 > 50%，或（成功率 < 30% 且至少失败 1 个）→ 触发增量重规划
第 3 级：全局超过 600 秒 → 拿已有结果强制合成
```

**追问与答法**

| 追问 | 答 |
|---|---|
| 为什么自研不用 LangGraph？ | 我的降级语义（单任务超时标记继续）框架不直接提供，在框架外打补丁不如写一层薄编排。**代价我认**：边界情况得自己兜，也没有现成的断点续跑 |
| `asyncio.gather` 里一个任务抛异常会怎样？ | 默认会取消其它任务；只有 `return_exceptions=True` 时异常才变成返回值，"单任务失败不影响整层"才成立 |
| 拓扑排序怎么检测环？ | Kahn 算法：队列空了但还有节点没出队，剩下的就是环 |
| 分层并发比全并发好在哪？ | 全并发会把 10 个任务同时打出去触发限流；分层保证同层无依赖可安全并发，且每层能独立控并发度 |

### 第 ③ 句 · Red-Blue 对抗（**改动最多**）

**原文**：

> Red Agent 从事实性/逻辑一致性/引用质量**多维度**攻击报告，Blue Agent 执行 **ADD/DELETE/MODIFY/VERIFY** 修复；内置评分收敛与震荡检测，三层 JSON 解析 fallback 将成功率从 **85%→95%**。

**修订后**：

> Red Agent 从**事实核查/幻觉检测/逻辑一致性/来源可信度/覆盖完整度五个维度**加权评分并定位问题，Blue Agent 按问题类型执行**就地修正/补充检索/整段移除三类**修复；内置评分收敛与震荡检测（已修复问题复现即终止），并对模型输出做**多级 JSON 解析兜底，解析失败降级为保守评分不中断流程**。

#### 改动 2：修复类型 **4 → 3**（去伪）

👉 [verdict.py:38-42 FixType 枚举](../src/adversarial/verdict.py#L38-L42)

```python
class FixType(Enum):
    IN_PLACE = "in_place"      # 就地修正：数字/日期/人名直接替换
    SUPPLEMENTARY = "search"   # 补充检索：无出处的论断触发新搜索
```

**如果已经被问到了怎么接**：
> "我实现的修复类型是三类：就地修正、补充检索、整段移除。**验证类操作我最终没有做成独立的修复类型**——因为验证是下一轮 Red Agent 攻击时自然会重新做的事，单独拆一类会造成重复。"

#### 改动 3：删掉 85%→95%（**最关键**）

**这个数字在全仓库查无出处。** 没有实验日志、没有结果文件、`experiments/` 目录不存在。

**兜底链的真实结构**：

```
调 LLM 拿输出
  ↓ 失败

整个对抗循环继续跑，不崩
```

**这比"85%→95%"好在哪**：它描述的是**降级设计**，而"85%→95%"只是个孤立的数字。面试官问"解析失败会怎样"，改后的表述直接给了答案。

**诚实 + 具体 + 把话题引回你会的地方**。

#### 收敛与震荡（原句"评分收敛与震荡检测"，保留并说清）

👉 [loop.py:161-176 `_check_convergence()`](../src/adversarial/loop.py#L161-L176) · [loop.py:102-115 震荡检测](../src/adversarial/loop.py#L102-L115)

**三个收敛条件（三选一）**：
1. 轮数用尽
2. 分数达标
3. 轮间变化量 Δ 低于阈值 ← **注意有 `round > 1` 前提**，因为第一轮没有可比对象，Δ 恒为 0

**震荡检测**：`已修复问题集合 ∩ 本轮问题集合` 非空 → 判定震荡，立即停止。

> **主动讲这个**：*"如果同一个问题修好又冒出来，说明修改在互相抵消，继续跑是浪费——所以我用问题集合求交集来检测震荡，命中就直接停。"* 这是这一条里最有说服力的设计。

### 第 ④ 句 · 压缩 + 共享记忆

**原文**：

> L1 Embedding 粗过滤→L2 TextRank 细筛选→**L3 原文保留**三级语义压缩，**显著降低长链路信息损失**；构建跨 Agent 共享记忆存储（SQLite+numpy 向量索引），写前自动去重与矛盾检测（启发式反义词+**语义对立**）并多策略消解。

**修订后**：

> **按上下文预算占用率自动分级触发**三级压缩（L1 Embedding 相关性粗筛→L2 TextRank 关键句抽取→**L3 LLM 层级摘要**），超限时以滑动窗口兜底；构建跨 Agent 共享记忆存储（SQLite+numpy **向量检索**），写入前执行语义去重与矛盾检测（基于**反义词表与否定词表**的启发式判定），并提供**多数投票/来源权重/LLM 裁定**三种冲突消解策略。

#### 改动 1：说清触发机制（补强）

👉 [compressor.py:30-33 触发阈值](../src/compressor/compressor.py#L30-L33)

```python
_L1_THRESHOLD = 0.60   # 用量 > 预算 60% → 启动 L1
_L2_THRESHOLD = 0.80   # 用量 > 预算 80% → 追加 L2
_L3_THRESHOLD = 0.95   # 用量 > 预算 95% → 追加 L3
```

**⚠️ 这三个数是"预算占用率"，不是"相似度"。** README 把它写成"cosine<0.6 丢弃"是错的。

**为什么补上触发机制更强**：它把"三级压缩"从一个**静态描述**变成了**有条件的工程决策**——面试官会看到你知道"什么时候该压"。

#### 改动 2：L3 "原文保留" → "LLM 层级摘要"（去伪）

👉 [compressor.py:249-284 `_l3_summarize()`](../src/compressor/compressor.py#L249-L284)

L3 是**逐文档摘要 → 聚合摘要**，是**生成式**压缩。

**原表述本身自相矛盾**：如果 L3 是"保留原文"，那它就不是压缩。

**改后可以这样讲**（面试加分）：
> "前两级是**抽取式**——只挑句子，不生成新内容，所以没有引入幻觉的风险；第三级是**生成式**——用 LLM 摘要，信息压缩率最高但也最贵，所以放在最后一级才触发。"

#### 改动 3：L1 阈值是自适应的（可用来自证读过代码）

👉 [compressor.py:198-207 自适应阈值循环](../src/compressor/compressor.py#L198-L207)

```python
for threshold in [0.25, 0.20, 0.15]:
    filtered = [t for t, s in scored if s >= threshold]
    if self.calculate_tokens(filtered) <= budget * 0.8:
        break
```

从 0.25 试起，过滤后仍超预算就降到 0.20、再降到 0.15。**这是"不预设一个固定阈值"的设计**，主动讲很加分。

#### 改动 4：矛盾检测去掉"语义对立"（降级表述）

👉 [memory_store.py:62-98 `_is_semantically_opposite()`](../src/memory/memory_store.py#L62-L98) · [memory_store.py:38-50 反义词表](../src/memory/memory_store.py#L38-L50)

真实实现只有两条规则：
1. **否定词检测**（不/没/无/非/未/not/no）
2. **6 组预定义反义词对**：增加/减少、好/坏、支持/反对、成功/失败、高/低、大/小

**"语义对立"这个词偏强**——它做不到语义层面。

> **主动亮缺点**：
> "我用的是反义词表 + 否定词检测的启发式。**局限很明显：抓不到语义层面的隐性矛盾**——两句话用完全不同的词表达对立的意思就漏了。**正确做法是用 NLI 模型判蕴含/矛盾关系**，这是我知道但没做的部分。"

#### 改动 5："numpy 向量索引" → "向量检索"（订正）

👉 [memory_store.py:328-361 `query_by_similarity()`](../src/memory/memory_store.py#L328-L361)

实现是**暴力点积** + `np.argsort` 取 Top-K，**没有 ANN 索引**。

**但这不是缺点，要主动说清楚**：
> "数据量在万级以内——1 万条 × 384 维约 15MB，暴力检索就是毫秒级，上 ANN 是过度设计。**要扩到十万级我会换 FAISS 或 pgvector**。"

⚠️ **不要说"我做了向量索引加速"**。说"暴力检索，但这个量级下够用"。

#### 改动 6：删掉"显著降低长链路信息损失"

**这句话在代码里找不到支撑**。全仓库里 `compress()` **只有一个调用点**——给规划器构建上下文时，且仅在字数 > 6000 时触发。

而真正会爆上下文的**研究 Agent 多轮循环**（`max_turns=10`）**完全没接压缩**。

> **被问到怎么接**：
> "目前接在规划器的上下文构建上。研究 Agent 的多轮循环我还没接进去——**那里才是上下文涨最快的地方**，是明确的待办。"

#### 三种消解策略（新增到简历）

👉 [memory_store.py:387-444 `resolve_conflict()`](../src/memory/memory_store.py#L387-L444) · [memory_store.py:446-493 三种策略实现](../src/memory/memory_store.py#L446-L493)

| 策略 | 什么时候用 |
|---|---|
| `majority_vote` | 多个 Agent 各自独立得出结论时，多数胜 |

### 第 ⑤ 句 · 评测体系

**原文**：

#### ⚠️ 关于"跑出来多少分"

**仓库里没有任何实验结果。** 所以：

- **不要主动报分数**
- **被问到就如实说**："评测流水线完整实现了，但完整跑一轮约 12 小时，我项目周期内没跑完大规模实验。"
- **立刻转向你能讲的**：指标怎么设计的、Judge 有什么偏差、Bootstrap 为什么用它

**12 小时这个数字本身就是你和面试官的共同语言**——它说明你做过资源测算，不是随口说的。

#### 统计三件套（记准参数）

👉 [stats.py:20-63 Bootstrap](../evaluation/metrics/stats.py#L20-L63) · [stats.py:108-116 Cohen's d](../evaluation/metrics/stats.py#L108-L116) · [stats.py:118-132 配对 t 检验](../evaluation/metrics/stats.py#L118-L132)

| 方法 | 参数/含义 |
|---|---|
| Bootstrap 置信区间 | `n_bootstrap=10000`、`confidence=0.95` |
