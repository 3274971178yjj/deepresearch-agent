## 第 0 步 · Python 语法工具包（第 1 包）

本讲会看到这几个新语法。**不用背，认识就行**——看到代码里出现时知道它在干什么。

| 语法 | 例子 | 【人话翻译】 |
|---|---|---|
| `Enum` 枚举类 | `class FixType(Enum): IN_PLACE = "in_place"` | 把"只允许取某几个值"的字段固定下来。就像红绿灯只能是红黄绿，不能是"紫色"。**面试含义**：修复类型只有 3 种这个事实，是代码写死的，不是随便说的 |
| `@classmethod` | `VerdictEngine.compute_overall(...)` | 不用先 `new` 一个对象就能调的方法。`VerdictEngine` 是一本"计算规则手册"，直接翻就行，不需要先把它买回家 |
| `dict[Dimension, float]` | `dimension_scores: dict[Dimension, float]` | 类型注解：一个"维度→分数"的字典。冒号后面只是**给人看的说明**，Python 运行时不管它 |
| `copy.deepcopy(x)` | `current = copy.deepcopy(report)` | 深拷贝：把文件**内容和子文件夹全部复印一份**。浅拷贝只复印了"文件夹外壳"，里面还是同一批纸。**面试含义**：对抗循环不修改原报告，改的是副本 |
| `set` 交集 `&` | `resolved_issues.intersection(set(verdict.issues))` | 找出"两个名单里都有的名字"。**面试含义**：震荡检测就是靠它——"我修好的问题"∩"这轮又出现的问题" |
| f-string 格式符 | `f"{score:.2f}"` | 保留两位小数。`.2f` = 小数点后 2 位 |
| `np.argsort(x)[::-1]` | `np.argsort(sims)[::-1][:top_k]` | 把数组**从小到大**排好，返回的是"下标"不是值。`[::-1]` 倒过来变成从大到小。**面试含义**：向量检索的"取 Top-K"就是这一行 |

## 第 2 步 · 简历第 ② 句：编排引擎（**你的主战场**）

**简历原文：**

> 基于 asyncio+Semaphore 自研多智能体编排引擎，实现 DAG 拓扑并发执行与 9 状态状态机任务生命周期管理，支持动态 replan 与三级降级策略（单任务超时→批量失败重规划→全局超时强制合成）。

**这一句是全项目最实的**，逐字对得上。要把它讲成亮点。

### 2.1 九个状态分别是哪九个

| # | 状态 | 干什么 |
|---|---|---|
| 1 | `IDLE` | 刚启动 |
| 2 | `PLANNING` | 调 Planner 把 Query 拆成 DAG |
| 3 | `DISPATCHING` | 按层并发执行子任务 |
| 4 | `COLLECTING` | 收结果、写共享记忆 |
| 5 | `SYNTHESIZING` | LLM 合成报告 |
| 6 | `ADVERSARIAL` | Red-Blue 对抗 |
| 7 | `REPLANNING` | 失败过多时增量重规划 |
| 8 | `DONE` | 正常结束 |
| 9 | `FAILED` | 异常结束 |

每个状态对应一个 `_do_xxx` / `_on_xxx` 方法，**这就是"显式状态机"的证据**：状态不是散落在代码里的 if-else，而是一张显式的转移表。

👉 **本地阅读代码**：[orchestrator.py:194-511 各状态的 _do_/_on_ 处理函数](../src/orchestrator/orchestrator.py#L194-L511)

> **面试口径**："我把任务生命周期显式建模成 9 个状态，每个状态一个处理方法。好处是任何时刻我都能回答'现在卡在哪一步'，也方便做降级决策——因为降级本质上是'在某个状态下决定要不要跳去另一个状态'。"

### 2.2 三级降级的**精确**触发条件

这是最容易被追到第二层的地方，**三个数字要背准**。

| 级别 | 触发条件 | 代码 |
|---|---|---|
| **第 1 级**：单任务超时 | 子任务 `asyncio.wait_for` 超时 → 标记 `TIMEOUT` 但不阻塞整层 | `_do_dispatching` 内部 |
| **第 2 级**：批量失败重规划 | **失败率 > 50%**，**或**（成功率 < 30% 且失败了至少 1 个） | 👉 [orchestrator.py:519-537 _should_replan()](../src/orchestrator/orchestrator.py#L519-L537) |
| **第 3 级**：全局超时强制合成 | `time.monotonic() - start > 600 秒` | 👉 [orchestrator.py:543-546 _is_global_timeout()](../src/orchestrator/orchestrator.py#L543-L546) |

`_should_replan` 的原文逻辑（要能复述）：

```
失败率 = 失败数 / 总数
若 失败率 > 0.5         → 重规划
若 成功率 < 0.3 且 失败数 > 0 → 重规划
否则                  → 不重规划
```

注意第 2 条是**两个条件同时成立**才触发。面试官可能问"成功率 20% 但失败数 0 呢？"——那不可能，成功率 20% 就意味着 80% 不是成功。**但你要能反应过来这个边界**，说明你真的读过。

**防死循环**：重规划有上限 [default.yaml:116 `max_replan_rounds: 3`](../configs/default.yaml#L116)。

### 2.4 这一句的追问清单

| 追问 | 答题要点 |
|---|---|
| 为什么自研不用 LangGraph？ | 我的降级语义（单任务超时标记继续）框架不直接给，与其在框架外打补丁，不如写一层薄编排。**代价我认**：边界情况全得自己兜，也没有现成的断点续跑 |

## 第 3 步 · 简历第 ③ 句：Red-Blue 对抗（**高危，逐字核**）

**简历原文：**

> Red Agent 从事实性/逻辑一致性/引用质量多维度攻击报告，Blue Agent 执行 **ADD/DELETE/MODIFY/VERIFY** 修复；内置评分收敛与震荡检测，三层 JSON 解析 fallback 将成功率从 **85%→95%**。

**这句话里有 3 处和代码对不上。** 先看真实情况，再看怎么处理。

### 3.1 五维攻击：真实的五个维度

👉 **本地阅读代码**：[verdict.py:45-51 Dimension 枚举](../src/adversarial/verdict.py#L45-L51) · [verdict.py:188-194 权重表](../src/adversarial/verdict.py#L188-L194)

| 维度 | 枚举值 | 权重 | 为什么权重这么排（**分析**） |
|---|---|---|---|
| 事实核查 | `fact_check` | **0.30** | 最高——幻觉是深度研究最致命的失败模式 |
| 幻觉检测 | `hallucination` | **0.25** | 次高——和事实核查互补（一个是"说错了"，一个是"编造了"） |
| 逻辑一致性 | `logical` | **0.20** | 内部自洽性 |
| 来源可信度 | `source_credibility` | **0.15** | 引用的质量 |
| 覆盖完整度 | `coverage` | **0.10** | 答全了没有 |

综合分是**加权平均**，权重和恰好 = 1.0：

👉 **本地阅读代码**：[verdict.py:210-230 compute_overall()](../src/adversarial/verdict.py#L210-L230)

**⚠️ 简历写"事实性/逻辑一致性/引用质量多维度"**——这三个词能对应上 `fact_check` / `logical` / `source_credibility`，**没说错但漏了两个**。建议补全成"事实性、幻觉检测、逻辑一致性、来源可信度、覆盖完整度五个维度"，因为**说得出"五个"和权重排序，是这一条最加分的细节**。

> **注意**：README 里写的"时效性"维度**在代码里不存在**。如果你照 README 背，会答出一个不存在的维度。

### 3.2 Blue 的修复类型：**只有 3 种，不是 4 种**

👉 **本地阅读代码**：[verdict.py:38-42 FixType 枚举](../src/adversarial/verdict.py#L38-L42)

| 枚举名 | 值 | 干什么 |
|---|---|---|
| `IN_PLACE` | `"in_place"` | 原地修正：数字/日期/人名直接替换 |
| `SUPPLEMENTARY` | `"search"` | 补充检索：无出处的论断 → 触发新搜索 |
| `REMOVAL` | `"removal"` | 整段移除：高置信度幻觉段落直接删 |

**没有 `VERIFY`。**

**怎么处理**：把简历改成"**原地修正 / 补充检索 / 整段移除三类修复**"。少一个词不损失分量，但去掉一个雷。

> 如果已经被问到了，诚实答："我实现的修复类型是三类，就地修正、补充检索和整段移除。**验证类操作我最终没有做成独立的修复类型**——因为验证是 Red Agent 下一轮攻击时自然会重新做的事，单独拆一类会重复。"

**这句话必须是真的想清楚了才说**，因为它是一个设计判断，不是借口。

### 3.3 收敛与震荡：两个刹车

**刹车 1 · 收敛（三选一）**

👉 **本地阅读代码**：[loop.py:161-176 _check_convergence()](../src/adversarial/loop.py#L161-L176)

```
① 轮数用尽     round_idx >= max_rounds
② 分数达标     overall_score >= score_threshold
③ 变化量收敛   round > 1 且 delta < delta_threshold
```

注意条件 ③ 有 `round > 1` 的前提——**因为第一轮没有上一轮可比，`delta` 恒为 0**，如果不加这个判断，第一轮就会因为"变化量为 0"直接停下。这是一个真实的边界处理，**面试讲出来很加分**。

👉 **本地阅读代码**：[loop.py:128-132 delta 的计算](../src/adversarial/loop.py#L128-L132) · [verdict.py:232-258 compute_delta()](../src/adversarial/verdict.py#L232-L258)

`delta` 用的是**欧氏距离**，不是简单绝对差。设计理由是"能同时捕捉多维度的联合波动"（代码注释原话）。

> **⚠️ 待确认**：五维欧氏距离的理论最大值是 √(5 × 10²) ≈ 22.4，而配置的 `delta_threshold` 是 **0.2**。**这个阈值相对量程来说极小**，意味着"变化量收敛"这个条件实际上很难触发，真正起作用的是"轮数用尽"和"分数达标"。这是一个**我建议你主动承认的点**，见第 6 步。

**刹车 2 · 震荡检测**

👉 **本地阅读代码**：[loop.py:102-115 震荡检测](../src/adversarial/loop.py#L102-L115)

```python
reappeared = resolved_issues.intersection(set(verdict.issues))
if reappeared:   # 我修好的问题，这轮又出现了
    oscillation_detected = True
    break        # 直接停，避免来回拉锯
```

**设计含义**：如果同一个问题"修好 → 又冒出来 → 再修好 → 又冒出来"，说明修改在互相抵消，继续跑是浪费。**这个设计意图是这一条里最有说服力的部分，可以主动讲。**

> 🚨 **但"主动讲"必须带上限定条件 —— 别照上面那段原话讲。**
> 那个 `intersection` 要求**逐字完全一致**，而 `Issue` 的相等性包含 `description`（模型生成的自然语言），所以**同一个问题在两轮里换个措辞就判不等、直接从交集里漏掉**。实测：
> `"2024年市场规模应引用IDC数据"` vs `"市场规模数字缺少 IDC 来源引用"` → **判不等**。
>
> **所以它的实际检出率远低于设计意图。** 面试官如果顺着问"你怎么判断两轮是同一个问题"，照原文答会当场卡住。
>
> **正确讲法**：承认意图（宁可漏报也不要误报，因为误报会在报告还有救时强制中止循环），同时承认灵敏度上限，并给出修法（用 `维度+位置+严重度` 做键、或上语义相似度）。
> **逐字话术与完整机制见** 👉 [面试知识库-项目二-对抗循环M5.md](面试知识库-项目二-对抗循环M5.md) §3.1.3 / §5.1

**对抗的轮数/阈值（⚠️ 最容易翻车）**

| 来源 | 轮数 | 分数阈值 | delta 阈值 |
|---|---|---|---|
| **函数默认值** | 3 | 8.0 | 0.3 |
| **实际配置（工程中用这个）** | **10** | **9.5** | **0.2** |

👉 **本地阅读代码**：[loop.py:48-62 函数默认值](../src/adversarial/loop.py#L48-L62) · [default.yaml:163-175 实际配置](../configs/default.yaml#L163-L175)

### 3.4 三个必须知道的实现真相

**真相 1：Red Agent 的五维是【串行】的**

👉 **本地阅读代码**：[red_agent.py:295 顺序 for 循环](../src/adversarial/red_agent.py#L295)

函数 docstring 写着"并行（顺序 await 但可外部 gather）"——**实际就是顺序 `await`，没有并发**。

**面试价值**：这是个**白送的改进点**。被问到就说："五个维度互不依赖，这里是串行的；改成 `asyncio.gather` 能直接提速到接近 1/5 的墙钟时间。这是我明确的优化项。"——**主动说出可优化点，比被问出来强得多。**

**真相 2：对抗只看报告的前 4000 字符 —— 而且这恰好造成一个结构性盲区**

👉 **本地阅读代码**：[red_agent.py:288-291 截断](../src/adversarial/red_agent.py#L288-L291)

```python
content_truncated = report.content[:4000] if len(report.content) > 4000 else report.content
```

### 4.1 三级压缩：真实的 L1 / L2 / L3

**先说最重要的一件事：0.6 / 0.8 / 0.95 是"预算占用率"，不是"相似度"。**

👉 **本地阅读代码**：[compressor.py:30-33 触发阈值](../src/compressor/compressor.py#L30-L33) · [compressor.py:114-160 compress()](../src/compressor/compressor.py#L114-L160)

```python
_L1_THRESHOLD = 0.60   # 用量超过预算 60%  → 启动 L1
_L2_THRESHOLD = 0.80   # 用量超过预算 80%  → 追加 L2
_L3_THRESHOLD = 0.95   # 用量超过预算 95%  → 追加 L3
```

`usage_ratio = current_tokens / actual_budget`，**触发条件是"现在用了多少预算"，不是"这段文字有多相关"**。

| 级别 | 做什么 | 技术 | 关键实现 |
|---|---|---|---|
| **L1** | 相关性过滤：丢掉和 Query 无关的段落 | Embedding cosine | 👉 [compressor.py:170-218 _l1_filter()](../src/compressor/compressor.py#L170-L218) |
| **L2** | 关键句抽取：从保留的段落里抽最相关的句子 | TextRank + query 偏置 | 👉 [compressor.py:220-247 _l2_extract()](../src/compressor/compressor.py#L220-L247) |
| **L3** | 层级摘要：先逐篇摘要，再聚合 | **LLM** | 👉 [compressor.py:249-284 _l3_summarize()](../src/compressor/compressor.py#L249-L284) |
| 兜底 | 还超预算就滑窗截断 | — | [compressor.py:157-160](../src/compressor/compressor.py#L157-L160) |

**L1 的阈值是自适应的**（这是第 5 处文档不符）——不是固定的 0.25，而是从 0.25 试起，如果过滤完还超预算就降到 0.20，再降到 0.15：

👉 **本地阅读代码**：[compressor.py:198-207 自适应阈值循环](../src/compressor/compressor.py#L198-L207)

```python
for threshold in [0.25, 0.20, 0.15]:
    filtered = [t for t, s in scored if s >= threshold]
    if self.calculate_tokens(filtered) <= budget * 0.8:
        break          # 够小了，就用这个阈值
```

**"L3 原文保留"是错的。** L3 是 **LLM 层级摘要**（逐文档摘要 → 聚合摘要）。而且这个说法**在逻辑上自相矛盾**：如果 L3 是"保留原文"，那它就不是压缩了。

**建议改写**："**L1 向量粗筛 → L2 图算法抽取 → L3 LLM 摘要**，前两级是抽取式（不新增信息，无幻觉风险），第三级是生成式（成本最高，所以放在最后）"——**这个说法更好讲，还能展示你懂抽取式 vs 生成式的取舍。**

### 4.3 共享记忆：去重 → 冲突 → 消解，三段链

👉 **本地阅读代码**：[memory_store.py:30-33 两个阈值](../src/memory/memory_store.py#L30-L33)

| 环节 | 阈值 | 含义 |
|---|---|---|
| **去重** | cosine ≥ **0.92** | 太像了，判为重复，不重复写 |
| **冲突** | **0.65 < cosine < 0.92** | 话题相关但内容对立 → 登记为冲突记录 |

**去重**：👉 [memory_store.py:263-283 _find_duplicate()](../src/memory/memory_store.py#L263-L283)——归一化后点积取 argmax，超过 0.92 就返回已有条目的 ID。

**冲突检测**：👉 [memory_store.py:285-325 _detect_conflicts()](../src/memory/memory_store.py#L285-L325)——在 (0.65, 0.92) 区间里逐条比对，判定"语义对立"才登记。

**"语义对立"怎么判的？** 这是简历里**偏强**的一处表述。真实实现是**两个启发式规则**：

👉 **本地阅读代码**：[memory_store.py:62-98 _is_semantically_opposite()](../src/memory/memory_store.py#L62-L98) · [memory_store.py:38-50 否定词表与反义词对](../src/memory/memory_store.py#L38-L50)

1. **否定词检测**：一方含否定词（不/没/无/非/未/not/no…）另一方不含，且去掉否定词后 Jaccard 相似度 > 0.5 → 判对立
2. **反义词对检测**：命中 **6 组**预定义反义词对 → 判对立

那 6 组是：增加/减少、好/坏、支持/反对、成功/失败、高/低、大/小。

**这是明显的受限方案**：它只能抓**显式**矛盾。抓不到"营收增长"vs"业绩下滑"这种**同义改写的隐性矛盾**。

> **面试怎么接（这条要主动亮）**：
> "我用的是反义词表 + 否定词检测的启发式。**局限很明显：它抓不到语义层面的隐性矛盾**——比如两句话用完全不同的词表达对立的意思。**正确做法是用 NLI（自然语言推理）模型判蕴含/矛盾关系**，这是我知道但没做的部分。"
>
> 简历建议改成："**基于反义词表与否定词的启发式矛盾检测**"，把"语义对立"去掉。

**三种消解策略**：👉 [memory_store.py:387-444 resolve_conflict()](../src/memory/memory_store.py#L387-L444)

| 策略 | 实现 | 什么时候用（**分析**） |
|---|---|---|
| `majority_vote` | 同 topic 下统计各 claim 的支持者数，多的胜 | 多个 Agent 各自独立得出结论时 |
| `source_weight` | `evidence_type 权重 × confidence` | 来源质量差异明显时。权重：primary 1.0 / secondary 0.8 / inference 0.6 |
| `llm_judge` | 调 LLM 输出 A 或 B；**失败则回退到 source_weight** | 两边都不确定时 |

👉 **本地阅读代码**：[memory_store.py:446-493 三种策略的实现](../src/memory/memory_store.py#L446-L493)

**注意 `llm_judge` 的兜底**：LLM 调用异常时**自动回退到 `source_weight`**（[memory_store.py:492-493](../src/memory/memory_store.py#L492-L493)）。这是"降级思想"在 M4 的体现，**主动讲很加分**。

### 4.4 "numpy 向量索引" —— 一个反直觉的提醒

👉 **本地阅读代码**：[memory_store.py:328-361 query_by_similarity()](../src/memory/memory_store.py#L328-L361)

检索就是**暴力点积**：`self._embeddings.dot(q_vec)` 然后 `np.argsort` 取 Top-K。**没有 ANN 索引**。

**但这不是缺点。** 配置里 `max_entries: 10000`，10000 条 × 384 维 float32 ≈ **15 MB**，暴力点积是**毫秒级**。

**真正的性能问题在插入**：👉 [memory_store.py:157-170 _add_to_index()](../src/memory/memory_store.py#L157-L170) 用 `np.vstack` 每插一条就重建整个矩阵（O(n) 拷贝，累计 O(n²)）。**这才是该改的地方。**

### 4.5 ⚠️ 一个必须知道的坑：Embedder 会静默降级

👉 **本地阅读代码**：[embedder.py:27-35 静默回退](../src/memory/embedder.py#L27-L35)

```python
try:
    from sentence_transformers import SentenceTransformer
    _SENTENCE_TRANSFORMERS_AVAILABLE = True
except ImportError:
```

### 5.3 统计部分（这一节最"技术"，也最容易加分）

👉 **本地阅读代码**：[stats.py:20-63 bootstrap_ci_paired()](../evaluation/metrics/stats.py#L20-L63) · [stats.py:108-116 cohens_d()](../evaluation/metrics/stats.py#L108-L116) · [stats.py:118-132 paired_t_test()](../evaluation/metrics/stats.py#L118-L132)

| 方法 | 参数 | 一句话解释 |
|---|---|---|
| **Bootstrap 置信区间** | `n_bootstrap=10000`, `confidence=0.95` | 反复重采样 10000 次，估出**指标的波动范围**。判断"这个分数是真的还是抖出来的" |
| **Cohen's d** | — | **效应量**：差异**有多大**。0.2 小 / 0.5 中 / 0.8 大 |
| **配对 t 检验** | — | 比较两组配对样本。**实现里失败时回退到 Bootstrap** |

**为什么用 Bootstrap 而不是只做 t 检验？**（高频追问）
> "t 检验假设数据近似正态，我样本量小（35 题），而且还想估计**指标本身的置信区间**，不只是 p 值。Bootstrap 不依赖分布假设，小样本更稳健。"

**p 值 vs Cohen's d**（高频追问）：
> "p 值只回答'差异是不是随机的'，**不回答差异有多大**。样本量一大，微小差异也会 p < 0.05。所以我两个都报：CI 看波动，Cohen's d 看效应大小。"

👉 **本地阅读代码**：[run_all_experiments.py:376-395 参数与说明](../scripts/run_all_experiments.py#L376-L395)
